# Move Health onto its own Turso WAL file

## Outcome

Health stores its tables in its own Turso WAL file, like the owners listed in
[Split capability databases](storage-files.md), and no longer writes to the shared database.

## Acceptance

- `crates/health` opens its owner file through `crates/sjel-native-wal`, and the service builds
  with `turso-wal`.
- A receipt-backed shared-store restore supplies the export. The owner file matches both
  Health tables row for row.
- The first scheduled backup of the owner file restores with exact row parity.
- `GET /ready`, `health metrics` and `health summary` pass against the live owner.

## Evidence

Health was added with two tables in the shared database (`crates/health/src/store.rs`).

A `turso-wal` feature now keeps both tables in an owner file named by `SJEL_HEALTH_DB_PATH`. The
default `libsql` build is unchanged, so the live service keeps the shared database until cutover.
Under `turso-wal`, `health import`, `metrics`, `imports` and `summary` send jobs to the owner
socket, and `health snapshot` requests a backup snapshot. `tools/backup.sh` registers the owner,
and `services/health-wal-backup` declares the backup unit.

The Health tests pass on both engines: 12 with `libsql`, 14 with `turso-wal`, including job
mapping and the refusal of a metric outside the catalogue. Clippy passes on both engines.
[`health-owner-rehearsal.sh`](../../research/benchmarks/storage-engine/health-owner-rehearsal.sh)
served a scratch owner file and imported a synthetic export through the CLI and the owner
socket. It read the values back without opening the shared database. An owner-snapshot backup
then restored three daily values and one import in isolation.

## Remaining cutover

Needs the operator, because it reads the live shared database and changes deployment config:

1. Hold Health, take a receipt-backed shared-store backup, and export both Health tables into
   the owner file.
2. Set `SJEL_HEALTH_DB_PATH` in the overlay, enable `health-wal-backup`, and build the service
   with `--no-default-features --features turso-wal` in `crates/health/service.toml`.
3. Run the remaining acceptance checks above against the live owner.
