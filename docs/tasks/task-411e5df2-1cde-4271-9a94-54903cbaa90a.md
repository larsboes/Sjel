# Import LinkedIn connections into People

## Outcome

Each first-degree connection in a LinkedIn `Connections.csv` becomes or updates one person in
Entities, with `linkedin` as the source of every value it writes.

## Acceptance

- Done: `entities-server sync-linkedin <Connections.csv> [--dry-run]` parses the export
  (`crates/entities/src/linkedin.rs`). It writes `emails`, `company`, `role`, `linkedin` and
  `connected_on` through `sync::apply`. Unit tests use synthetic rows only.
- Done: on a temporary store, a second run of the same file reported 2 unchanged. A changed
  company and position updated 1 person.
- Done: given the export folder, `messages.csv` sets `last_contact` per linked person from
  participant URLs and dates only. On a temporary store, a second run set 0.
- Done: dry run against the real store and export: 472 records, 405 to create, 67 matched by
  exact name, 0 refused, 5 rows without a name or URL skipped.
- Done: real write by the operator: 472 records, 405 created, 67 linked by name, 0 refused.
  Messages: 75 profiles, 56 linked to a person, 50 last contacts set.
- Open: the Import router hands `Connections.csv` to Entities. Another session holds
  `crates/import/src/route.rs` uncommitted.
- Open: Import offers a dry-run preview before the write.
- Open: the `posts-people` mention resolution reads the `linkedin` external ID.

## Constraints

- Connection data is C2. It stays in the overlay store and goes to no cloud model.
- The CSV splitter copies `crates/cv/src/linkedin.rs`. Extract one shared reader when
  `Cargo.lock` has no other session's changes.
