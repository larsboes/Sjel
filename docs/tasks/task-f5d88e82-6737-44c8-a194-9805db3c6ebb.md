# Remove Pi pending queues and follow approved plans

## Outcome

Pi executes approved plans without deferred question or permission queues. Questions resolve
material planning gaps, not settled choices or routine implementation. Existing routine autonomy
remains intact; removing the entire command policy requires a separate user decision.

## Acceptance

- Question cards have no idle deadline, pending map, topic-based cache or `/decisions` command;
  cancellation preserves submitted answers and grants no unanswered choices.
- Learn renders direct question cards without timeout or queue-resumption controls.
- Permission cards have no deferred map, retry tokens, **Defer** option or
  `/permissions pending` flow; cancellation grants nothing. Existing routine permissions and
  consequential-effect gates remain unchanged unless explicitly authorized otherwise.
- Plans state scope, acceptance and blocking decisions; execution does not re-confirm settled
  choices. No additional decision journal or session-cache mechanism is introduced.
- Focused tests and installed-Pi type checks pass; reload and session-switch smoke checks confirm
  no pending state or stale approvals survive.

## Implementation and verification

Question, Learn and permission queue removals are implemented in source. The question suite is
now `tools/questions.test.ts`; permission lifecycle tests cover cancellation, immediate-only
approvals, working-directory binding and stale dialogs after session changes. Owner READMEs
match the implementation. Broader guard removal is deferred because it has no explicit approval.

`tools/work check` and `git diff --check` pass. `tools/local-build` returns exit 3: build and
test commands remain blocked by the active On the go policy; no exception was authorized.
Runtime status discovery also fails because the enabled `web-links` capability is absent.
