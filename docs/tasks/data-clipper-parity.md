# Accept browser Clipper parity

## Outcome

Accept browser Clipper parity through the existing owner, with implementation and live acceptance recorded separately.

## Acceptance

- Verify page/selection/URL capture with metadata and edits, authenticated/client-rendered content, shortcuts/context menus/error feedback and file/clipboard export.
- Verify Reader content/images/headings/code/footnotes/settings, persistent text/element highlights on revisit, search/export and each highlight mode.
- Verify template import/export/order/triggers, variables/selectors/schema/filters/logic/loops/properties and create/overwrite/prepend/append destinations with explicit conflict rules.
- Verify selected Interpreter behavior, model/provider/context/filter semantics under classification and credential rules; preserve full versioned clip documents before feed projection/enrichment.
- Exercise side panel, offline recovery, duplicate identity, browser restart, migration and backup/restore. Assess each browser's native-messaging/host permissions independently; record each parity row as passed or a named gap.
