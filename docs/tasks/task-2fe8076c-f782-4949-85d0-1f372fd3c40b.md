# Accept the loop-check hook

## Outcome

Claude Code sessions get one context line when a tool call repeats with the same input, or when
two calls alternate without progress (`crates/sjel-cli/src/loop_hook.rs`, `tools/loop-hook`).

## Acceptance

- Done 2026-11-19: `tools/loop-hook` answers a synthetic `PostToolUse` payload, sent four times,
  with exactly one `additionalContext` message.
- Add the `PostToolUse` entry for `<sjel>/tools/loop-hook` to `~/.claude/settings.json` beside the
  Pack drift hooks, and list it in `Packs/harness/README.md`.
- One real session shows the message once and no message on ordinary repeated reads.

`tools/loop-hook` never builds: with stale `sjel-cli` sources it answers in 10–20 ms from the
existing binary, and it exits 0 silently when no binary exists. A `sjel-cli` release rebuild
takes about 10 s, which a 5 s hook timeout would cut off on every call.

Unit tests pass (`tools/cargo-hermetic test -p sjel-cli --locked loop_hook`).
