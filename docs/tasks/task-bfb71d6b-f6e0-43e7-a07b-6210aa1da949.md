# Run every service from one release build directory

## Outcome

Each release binary is built once, in the checkout's `target/release`, which service manifests
already name. The shared Cargo target holds no second release tree.

## Acceptance

- Launchers that resolve `${CARGO_TARGET_DIR:-$SJEL_ROOT/target}/release` resolve the checkout's
  `target/release` through one helper in `tools/lib/paths.sh`.
- A launcher rebuild cannot terminate a running service that uses the same binary. Verify by
  rebuilding a binary that a live service uses and confirming that the service keeps running.
- After `ps` shows no process running from `~/.cargo-target/release`, remove that tree through
  `sjel storage reclaim`. Record the free-space change.

## Evidence

`tools/lib/paths.sh` defines `SJEL_RELEASE_TARGET` as the checkout's `target/`. The 14 launchers
that build release binaries use it for the binary path and as the build's `CARGO_TARGET_DIR`.
`tools/lib/sjel-cli.sh` falls back to the same path when a caller does not source `paths.sh`.
`tools/loop-hook` uses the checkout path directly. With an interactive `CARGO_TARGET_DIR` set,
`sjel-storage`, `projects`, `sjel-capability-auth`, `documents`, `sjel-mcp` and `sjel-contain`
resolved to the checkout's tree.

A scratch binary kept running while Cargo rebuilt it and while `codesign -f` re-signed it. Both
steps write a new inode. The release-binary refusal in `sjel cargo` therefore protects against
mixed build trees, not against process termination.

The overlay storage policy replaces the protected shared release entry with a reclaim class.
The forced reclaim removed 41.2 GB, and volume free space rose by 39.5 GiB. Three `sjel-mcp`
servers and one `sjel-contain` process held binaries in the tree and kept running; a Calendar
read through the session's MCP server succeeded afterwards. The service runner, capability
authentication, FDA launcher, storage launcher and GPUI install shell tests pass.
`tools/sjel.test.sh` fails on its `cargo <args...>` help assertion with and without this change.
