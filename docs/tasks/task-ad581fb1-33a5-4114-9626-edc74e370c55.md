# Rehearse Turso 0.8.4 before upgrading the owners

## Outcome

All Turso WAL owners run one engine version, 0.8.4, after a rehearsal shows that it opens and
restores the existing owner files. Pull request #289 merges only after that rehearsal.

## Acceptance

- `crates/sjel-native-wal` and `crates/inventory` pin the same Turso version.
- `research/benchmarks/storage-engine/inventory-backup-rehearsal.sh` and
  `entities-native-rehearsal.sh` pass with 0.8.4 on copies of the live owner files.
- A 0.8.4 snapshot of each owner restores into SQLite with exact row parity and passes
  integrity and foreign-key checks.
- The owner crates' tests pass with the `turso-wal` feature.

## Evidence

`crates/sjel-native-wal` and `crates/inventory` pin Turso 0.8.4, and every Turso crate in
`Cargo.lock` resolves to 0.8.4.

The [engine upgrade rehearsal](../../research/benchmarks/storage-engine/README.md#engine-upgrade-rehearsal)
restored the latest receipt-backed backup of all nine owners. Turso 0.8.4 committed and rolled
back probe writes on each file. SQLite integrity and foreign-key checks passed, and each full dump
matched the dump before the probe. Turso 0.8.3 passed the same run as a control.

`inventory-backup-rehearsal.sh` restored all ten Inventory tables and sequence counters, and the
0.8.4 `inventory` binary served the restored catalogue. `entities-native-rehearsal.sh` passed
with the 0.8.4 `entities-server`: native owner, private job socket, scheduled backup command and
receipt-backed restore.

On the `turso-wal` path, these owner test suites passed with no failures: Calendar 196,
Documents 53, Finance 255, Entities 52, Places 82, Punctuality 39, Transit 121, Inventory 68
and Software 18. The live services move to 0.8.4 on their next refresh.
