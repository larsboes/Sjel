# Run every service from one release build directory

## Outcome

Each release binary is built once, in the checkout's `target/release`, which service manifests
already name. The shared Cargo target holds no second release tree.

## Acceptance

- Launchers that resolve `${CARGO_TARGET_DIR:-$SJEL_ROOT/target}/release` resolve the checkout's
  `target/release` through one helper in `tools/lib/paths.sh`.
- A launcher rebuild cannot terminate a running service that uses the same binary. Verify by
  rebuilding a binary that a live service uses and confirming that the service keeps running.
- After `ps` shows no process running from `~/.cargo-target/release`, remove that tree through
  `sjel storage reclaim`. Record the free-space change.

## Evidence

The service runner forces `CARGO_TARGET_DIR=<checkout>/target` (`crates/sjel-cli/src/runner.rs`),
and every `service.toml` names `target/release/<bin>`. Interactive shells export a shared
`CARGO_TARGET_DIR`. The 17 launchers that fall back to it build a second copy of each release
binary there. On 2026-11-20, 18 service binaries ran from the checkout's tree (27 GB), and
`sjel-mcp` and `sjel-contain` ran from the shared tree (41 GB).

`sjel cargo` states that replacing a live service binary terminates the service
(`crates/sjel-cli/src/help.rs`). The split tree is therefore also a safety boundary. Moving the
launchers changes that boundary and needs the verification above.
