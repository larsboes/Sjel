tools/intake — read third-party agent tooling before it reaches an agent.

  tools/intake scan <dir> [--against <dir>]
        The fixed rules: instructions aimed at the agent, hidden characters, fetch-and-run,
        exfiltration endpoints, credential paths, hooks and broad tool grants. With
        --against, only what is new relative to that copy is read.
  tools/intake review <dir> [--against <dir>] [--source <name>]
        The model review on the `intake_review` inference role (a c0 cloud role). It adds
        findings; it cannot clear one. With --source, a completed review records reusable
        evidence tied to content, baseline, model settings and the current intake policy.
  tools/intake review <dir> --source <name> --reviewer claude
        A coding harness reviews the whole tree: a fresh `claude -p` with read-only tools in a
        directory that holds only the staged files. Records a receipt with the harness, model
        and digest. The gate then uses that receipt in place of the model review for exactly
        that digest. A medium or high finding still holds; only `approve` clears it.
  tools/intake gate <dir> --source <name> [--against <dir>]
        Both, fail-closed: a missing or failed model review holds the content. Passes an
        approved digest at once. Holds (exit 2) on a medium or high finding. An unapproved
        --against baseline is ignored: the candidate is read in full.
  tools/intake approve <dir> --source <name> [--version <v>]
        Records the digest of exactly this copy, after a person read the findings.
  tools/intake version <source>
        The last approved version.

Exit codes: 0 passes, 2 holds, 1 is an error. State: ~/.local/state/sjel/intake/.
